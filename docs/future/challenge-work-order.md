## Planning decisions this work order encodes

Settled with Michael 2026-08-05 in the pre-review concern walk, each written back into the spec. The nine mercurius rounds that followed settled further semantics — tier assignments, checkpoint coordinates, identity, terminal rules — tagged inline throughout this document as `(round-N …)` where each lands; the round logs and journal carry their full dispositions:

1. **World-persisted captures.** A value a later challenge needs is deposited into the world (`w.Put`/`w.Get`), a dd-marshaled file under the world root that rides the checkpoint. Locals are challenge-local by nature; the deposit is what keeps `--from` exact. The reference suite requires this (the stale-snapshot digest crosses the 8→8b boundary).
2. **Quiesce at every boundary.** Supervised processes stop before each snapshot and restart after. No snapshot is ever taken under a live writer (the server holds `store.db` open under WAL for its lifetime), and full and resumed runs reach every challenge through the same bounce, so they can never disagree about the world a challenge starts in. No keep-alive knob until a consumer demonstrates need.
3. **World home and lifecycle.** The world lives in a gitignored `.challenge/<gauntlet>/` beside the suite — stable absolute path, because the product records absolute paths in its state (reef's store does, from the first `container init`). One generation of history: a fresh run resets, a failed run leaves world + checkpoints + partial transcript as the resumable session, `--clean` discards explicitly, a lock file makes a concurrent second run refuse loudly.
4. **Snapshot cost accepted for v1; checkpointing is policy.** Reflink-first honest copy, cost measured on the real port (the seam census's revisit trigger). Hardlink mode is explicitly disqualified for the reef gauntlet — its narrative mutates tree files in place. Checkpointing defaults on with per-challenge opt-out; resume is the save-point model (restore the greatest checkpoint *strictly before* the target, replay forward, execute the target against its predecessor's world — refined in round-4 C2).
5. **One work order, three stages.** Stage 1 library + toy consumer (this repo); stage 2 the port (archive repo); stage 3 the seal. Dev wiring via untracked `go.work`, never load-bearing for a landed commit: challenge tags and publishes `v0.1.0` inside stage 2, before the archive commit that deletes the bash, and that commit pins the tag (proven `GOWORK=off`).
6. **Build outside the model.** The consumer's `Bootstrap` hook produces the binary (engine-executed after the lock — refined in round-5 C1); the world holds state only; the binary lives beside the world and no checkpoint contains one. Resume presses current code against restored state — the debug loop, and itself a pressure test.
7. **Terminus enforces the import seam.** challenge vends the import-rule quality in its own repo; our terminus-canon adopts it directly as part of this arc. No `go/packages` runtime check in core. The vocabulary defines mirror structs of product state formats — deliberate duplication; drift is signal.
8. **Small clarifications.** The suite asserts the piped (non-TTY JSON) dl rendering, relying on dl's default rather than forcing an override; TTY-pretty is out of scope. Free-port allocation joins the core vocabulary. Navigation (`--from`/`--only`/`--list`) is standalone-face-only; the go-test face runs the gauntlet whole.

- **Transport truths the port must preserve.** Operational failures return through fang: exit 1, message rendered exactly once, no stack trace (`exercise.sh:60-72`, both the command-error and PersistentPreRunE arms). A failed run's exit verdict is the wire status (`:257-260`). Completed-with-errors exits **zero** with the loud summary — the run finished; the failure count is not the exit verdict (`:300-311`). ## Shape of the change

### The challenge library (this repo)

One package, `challenge` — small enough to audit is the design bar, and a flat package keeps the audit surface flat. Renderers and faces are files in the package, not subpackages; the toy consumer lives under `internal/`.

- **`world.go`** *(landed in 1a as `world.go` + `home.go` + `session.go` + `runState.go` — one primary type per file, per camelcase-file-naming)* — the world handle and its home. `.challenge/<gauntlet>/` holds `world/` (the checkpointed root), `bin/` (build artifacts, never checkpointed), `checkpoints/<NN>-<name>/`, `logs/`, `transcript.md`, and the session state beside them: the run pointer, the session identity minted at reset, and the corridor's recorded shape — ordered challenge names with their checkpoint policies (round-5 C2). Harness state splits by what it describes: state that describes the world *at a boundary* — the KV store and the process registry, dd-marshaled under a reserved `world/.harness/` — lives inside the checkpoint image, so deposits and registered fixtures roll back with every restore; state that describes the *session* — the lock, the run pointer, logs, the transcript — stays outside and survives it. (The reef vocabulary keeps product trees in named subdirs — `ws/`, `nas/`, `usb*/` — so `.harness/` sits beside them, out of product reach by construction.) The lock is `.challenge/<gauntlet>.lock` — a *sibling* of the gauntlet directory, outside every subtree that reset, restore, or `--clean` mutate, so the locked inode is never unlinked by the operations it guards. Every lifecycle operation acquires it first and mutates only the tree's children; `--clean` empties the tree but never unlinks the lock itself. Surface: `Dir(rel)` absolute paths under `world/`, `Put`/`Get` (the KV — decision 1), `FreePort()` (bind `:0`, return), env management, `WriteFile`/`ReadFile`/`Exists`/`Absent`/`SameBytes` filesystem assertions recording findings. Observation tiers (round-2 C4): `Get` of a missing or corrupt deposit, and any unreadable harness-owned path, are harness faults; `Absent` passes only on `ENOENT` — any other error faults, never reads as absence.
- **`process.go`** — supervision. Challenges register long-lived processes (`w.Start(name, literal, readiness)`); the spec (command, readiness probe, env) persists in `world/.harness/` so it rides checkpoints and resume knows what to restart — and rolls back with a restore, so a resumed run never starts a fixture a later challenge registered. All harness-spawned processes — one-shot commands and supervised fixtures alike — start in their own process groups (`Setpgid`, round-5 C4), isolated from the runner's foreground group: a tty Ctrl-C reaches only the harness, interruption provenance is recorded first, and children are terminated only by the harness's hand. Quiesce = SIGTERM, bounded wait, timeout escalates to SIGKILL **and a harness fault** (a process that won't die cleanly invalidates the run — decision 2's honesty depends on clean closes). Restart = re-launch from spec + readiness probe. Logs append under `logs/`; the harness tracks a per-instance offset and scans only each instance's *new* window at each quiesce — exactly-once evidence, so an old panic is never re-attributed by a later boundary or a resumed run. A supervised process found dead before its requested quiesce is a crash event in its own right, marker or no marker. Process-start classification (round-3 C5): spawn failure or invalid process/probe configuration is a harness fault (exit 2); a process that dies while starting is a crash-class product finding; live-but-never-ready at the bounded timeout is a product-surface finding. Both product-caused arms are terminal (round-4 C3): the invocation ends as findings (exit 1) with remaining challenges recorded as not-run — never a corridor marched against a fixture that does not exist. The no-checkpoint clause is scoped to failures *during challenge execution* (round-5 C3); a failure during the automatic boundary restart strikes after publication, and the checkpoint stays — a truthful closed world after a completed challenge — with the terminal finding attributed to the *upcoming* challenge, body not-run. Resume from the retained boundary retries the restart, which is exactly the debugging entry point wanted.
- **`run.go` / `result.go`** — the command channel. Literal parsing: whitespace split, `{}` placeholders substitute arguments as whole argv tokens, no shell, no quoting — a token containing spaces always rides a placeholder. `w.Run(literal, args...)` executes immediately; `w.Cmd(literal, args...).Stdin(s).Env(k, v).Run()` is the builder for the armed cases (the declined prompt, the foreign-workspace probes). `Result{Exit, Stdout, Stderr, Msgs}` — msgs parsed from dl JSON lines on both streams. Fluent assertions record findings: `ExpectExit`, `ExpectMsg` (parsed), `ExpectMsgOnce` (counts occurrences in the raw streams — the transport-discipline check), `ExpectOut`/`ExpectErr` (raw substring, the go-pretty channel), `Capture(regex)`. Capture semantics (round-5 A1): it reads the combined raw streams — stdout then stderr, the same surface the crash scan reads; the reference digest appears literally inside the raw dl JSON line, so no parsed-message indirection is needed — and returns the first capture group when the pattern has one, the full match otherwise; its toy pin is the `OLD_SNAP` case itself. Channel tiers (round-6 C1): a failure to issue at all — malformed literal, missing harness-owned binary, spawn error — is a harness fault, exit 2; no zero-valued `Result` is ever manufactured. Default verdict (round-7 C1): every completed command result carries an implicit `ExpectExit(0)` and every HTTP result an implicit success-status expectation, each displaced by an explicit call; failure of the implicit expectation is an ordinary assertion-class finding — the bash's silent `>/dev/null` setup lines become loud in the port. Observation tiers (round-2 C4): an invalid expression is a harness fault; `Capture` requires exactly one usable match — zero or ambiguous matches record a product-surface finding that is *terminal for the invocation* (round-4 C1): the run unwinds as findings (exit 1, never 2), remaining challenges record as not-run, and no checkpoint publishes for the broken challenge. A failed §8 capture must never ripen into §8b's missing-deposit harness fault — the break surfaces where it happened, wearing the right tier. Crash detection is automatic on every invocation and evidential as well as textual: `panic:` or `goroutine ` in any stream, or termination by signal, records a crash-class finding without an explicit check; marker and exit evidence for one crash coalesce into one finding. Termination provenance (round-3 C3): kills the harness itself initiated — interrupt cancellation, quiesce, the unwind — are excluded from crash classification; only unsolicited deaths count. Crashes are terminal (round-6 C2): the invocation ends as findings and no checkpoint publishes for the window's challenge — post-crash state never enters the save-point chain; the boundary-restart exception (round-5 C3) stands. Assertions remain the only non-terminal finding class.
- **`http.go`** — the wire channel. `w.Get`/`w.Post`/... against a base URL registered in world meta; `HTTPResult{Status, Body}` with `ExpectStatus`, `ExpectBody` (substring), and dd-decode into caller-supplied structs for structured assertions. Channel tiers (round-6 C1): an unparseable URL or malformed request is a harness fault; transport failure on a well-formed request — refused, reset, timeout at the product's shipped surface — is an invocation-terminal product-surface finding, excluded when recorded harness cancellation caused it, and coalesced with supervised-death evidence into one crash finding rather than two reports. Coalescing is instance-scoped (round-8 C1): each request carries the named fixture instance its base URL is registered to in world meta, and only same-instance evidence merges — an unrelated fixture's death stays its own finding. Decode tiers (round-4 C4): an invalid decode request or destination is a harness fault; a body that will not fit the mirror is a product-surface finding, invocation-terminal per the dependent-data-flow rule — the same tiers govern typed dd reads of product state files through the vocabulary's mirrors, which is what makes "drift is signal" a mechanism rather than a slogan.
- **`checkpoint.go`** — snapshots and the save-point model. `copyTree`: per-file `FICLONE` ioctl with transparent fallback to full copy — `--reflink=auto` semantics in-process, no external `cp` dependency. The copy contract is explicit and covers more than bytes: regular-file bytes, file and directory mode bits *and modification times* (directory times applied after their children are written, since writing children re-stamps the parent — round-3 C4: reef is a scanner, and mtimes are world state to a scanner), empty directories, and symlinks preserved as links (never dereferenced); any other node type (socket, device, fifo) is a harness fault, never a silent skip — a snapshot that cannot be faithful refuses to exist. Publication is atomic (round-2 A1): a checkpoint builds under a temporary sibling and renames into its canonical name only when the copy completes, so a failed or interrupted copy is never selectable by the resume resolver. The corpus demands this: 14b's `chmod` means mode bits are world state. Hardlink cloning as an explicit opt-in flag (never for reef — decision 4). Resume resolution (round-4 C2): checkpoints are post-challenge boundaries; `--from N` selects the greatest checkpoint *strictly before* N, replays intervening challenges, then executes N — N's own checkpoint is never a candidate for reproducing N. The fresh world is checkpointed as genesis (boundary zero) at reset, so the first challenge is no special case. `--only` requires the immediate predecessor's snapshot and refuses plainly when it is absent. Restore advances a frontier (round-3 C1): after a successful restore at boundary N, every checkpoint beyond N is removed before execution continues — the chain never holds two futures. Navigation validates topology before restoring (round-5 C2): the current gauntlet's prefix through the target must match the session's recorded prefix exactly; any divergence — inserted, removed, renamed, reordered — is a harness fault naming the session id and the divergence point, with `--clean` as the remedy. A valid suffix-branch rebases the session (round-6 C3): after the frontier clears the abandoned future, the recorded corridor shape and checkpoint policies are replaced with the current gauntlet's before replay publishes anything — the next navigation validates against the corridor that actually exists. Every invocation mints a run id, stamped through the run model, the transcript's attempt sections, and the checkpoints it publishes.
- **`model.go`** — the run model, pure data: gauntlet identity, per-challenge records, steps (cmd / http / fs / note), findings by class, verdicts, timings. Four finding classes per the seam census (round-8 C2): harness fault (aborts, exit 2), crash (highest-order, terminal), *break* (product-surface failure severing dependent flow — terminal, exit 1, below crash), assertion (counted, corridor continues, exit 1). The class rides the model and every renderer names it.
- **`renderConsole.go` / `renderTranscript.go`** — walkers only. Console reports live; the transcript renders markdown incrementally (appended as steps complete), so an aborted run leaves the partial document as the reproduction narrative. Attempts separate visibly (round-2 A2): a resumed invocation opens a new attempt section, and every verdict is per-invocation, computed only from work that invocation executed.
- **`gauntlet.go` / `engine.go`** — `Gauntlet{Name, WorldHome, Bootstrap, Challenges}`, `Challenge{Name, Doc, Fn func(*W), NoCheckpoint bool}` (`Doc` carries the ported provenance prose). `WorldHome` is a required absolute path — the home is declared, never discovered — and both faces resolve it independent of working directory, so standalone, `make`, and go test's temporary binary land on one world. `Bootstrap` is a consumer-owned pre-run hook the *engine* executes after the lock is acquired and before reset or restore (round-5 C1): the consumer owns what it does (build knowledge stays out of core, decision 6), the engine owns when. Core prescribes *nothing* about a bootstrap's content — it is an opaque `func(*W) error`, and no project shape (go build, npm, make, none of it) is assumed by the harness (round-9 A1); shared bootstrap helpers are vocabulary candidates under the three-consumer promotion rule, not core. Run sequence, lock held throughout: acquire lock → bootstrap → reset or restore → corridor. No invocation touches `bin/` — or anything — before it holds the lock. Engine loop per boundary: run challenge → quiesce processes → snapshot (unless opted out) → restart processes → next. Couplings established by landed 1a, binding on the engine: **the engine never publishes genesis** (`home.reset` owns boundary zero — a generation without its zeroth boundary is a coordinate system with a hole); **the engine calls `home.navigate`, never its pieces** (session load → incomplete-prune guard → prefix validation → resolve → record intent → restore → prune → rebase → clear is one un-bypassable operation); **the engine recovers the private unwind sentinel** that terminal findings (fault/break/crash) panic through `W.record` — challenges are ordinary func bodies, and leaving one mid-body is the only honest "terminal"; and `--clean` leaves a tree `navigate` rightly refuses (`loadRunState` faults on absence — fail-closed), so clean is always followed by a fresh reset, never a resume. The engine is the only owner of that ordering, and the unwind is engine-owned and unconditional: every return path — clean finish, findings, harness fault — performs best-effort quiescence of all supervised processes before the run model is returned; no process restarts when no further challenge will execute; a cleanup failure remains a harness fault, reported loudly.
- **`main.go` / `gotest.go`** — the two faces, walkers with no logic. `challenge.Main(g)`: `--from`, `--only`, `--list`, `--clean`, `--world-home` (overrides `Gauntlet.WorldHome`, applied before lock derivation — round-6 C4), transcript path, verbose; exit 0/1/2. The face owns signal handling (round-2 C3): SIGINT/SIGTERM cancels in-flight work, runs the engine's unwind, records the run as invalid, exits 2 — the existing harness-fault tier, no new class. `challenge.T(t, g)`: challenges as subtests, whole-gauntlet only, documented for use behind `//go:build challenge` in the consumer.

**The toy consumer** (`internal/toy/` + the library's own tests): a tiny df-shaped product binary — emits dl msgs, writes a dd state file, serves a trivial HTTP endpoint, and carries flags to panic, prompt on stdin, sleep-on-SIGTERM (for quiesce-timeout testing), and never-ready (start but refuse the readiness probe). The library's test suite drives a toy gauntlet through real subprocess execution: resume exactness (run, kill, `--from`, byte-compare worlds), checkpoint honesty (mutate bytes, mode bits, mtimes, and a symlink after a snapshot; restore; compare content *and* metadata, mtimes included), the unsupported-node refusal (including that the failed checkpoint is never selectable — atomic publication), the rollback pin (a KV value set and a process registered *after* a save point both vanish when that point is restored), the branching-resume pin (fail late, resume early, verify the abandoned future's checkpoints are removed and unselectable — plus the fail-closed arm, round-9 A2: inject a pruning failure midway and assert navigation refuses until `--clean`, so an incomplete prune can never expose the abandoned branch), the boundary-coordinate pin (a non-idempotent challenge whose own checkpoint exists: `--from` it and assert it ran against the predecessor's world, never its own aftermath), the topology pin (run, reorder the toy gauntlet, attempt `--from`: harness-fault refusal naming the session and divergence point; `--clean` recovers — with a second act per round-6 C3: change only the suffix, resume across the branch successfully, then resume again targeting the new suffix and assert the rebase made it resolve), opt-out replay, quiesce ordering, the abort-unwind pin (clean completion, a mid-challenge harness abort, *and* SIGINT/SIGTERM delivered only to the harness parent — each leaves no live children and no held product locks; the signal arm runs as a subprocess test in two forms — SIGINT to the parent only, and SIGINT to the *whole foreground process group* the way a terminal delivers it (round-5 C4) — each asserting the interruption harness fault, *zero* product-crash findings, and nothing left alive), stdin and env arms, the transport-default pin (round-6 A1: the child's environment carries no harness-added `DL_USE_JSON`, and message parsing succeeds through an ordinary pipe — dl's shipped default-selection stays under test), crash detection (marker, signal death, and marker-free server death — exactly one attributed finding across repeated boundaries and resume; the mid-challenge command-panic and killed-fixture arms each end the run at exit 1 with no checkpoint for that challenge), all three exit tiers, the process-start tier pins (spawn failure faults; die-during-start is a crash finding and never-ready a product finding, both terminal — the run ends as findings with remaining challenges not-run and no checkpoint for an in-challenge break; a die-on-boundary-restart arm asserts the completed challenge's checkpoint is retained and the finding attributes to the upcoming challenge), the observation-tier pins (bad regex faults; missing deposit faults; expect-absent distinguishes `ENOENT` from unreadable; a failed capture is invocation-terminal — pinned by `Capture`→`Put` in one challenge and `Get` in the next with the capture forced to fail, asserting exit 1 and zero harness faults), the decode-tier pins (a state file with a mutated field name and a response body that won't decode — each exit 1, attributed to the product surface with rendered class `break` per round-8 C2, zero harness faults), the channel-tier pins (a nonexistent binary faults at exit 2; ### The reef port (archive repo)

- **Location**: `reef/test/gauntlet/` (package `main`, the suite binary) + `reef/test/gauntlet/vocab/` (the vocabulary package). Both under the import rule.
- **Consumer bootstrap** (round-3 C2): one shared function in the suite package — ensure SPA `dist/` (npm install/build when missing), then *unconditionally* `go build` reef into the world-adjacent `bin/` (decision 6; go's incremental cache makes the no-change case sub-second) — installed as the gauntlet's `Bootstrap` hook and executed by the engine in both faces *after* the world lock is acquired (round-5 C1), so a concurrent invocation is refused before anything mutates. The freshness guarantee is scoped honestly (round-9 A1): it covers the *product binary* — rebuilt unconditionally, every run — while SPA assets rebuild only when `dist/` is absent, which suffices because browser coverage is out of scope beyond the serves-the-shell smoke. A verdict is about the Go code you have, never the binary you happen to still have.
- **Suite `main()`**: construct the gauntlet — default home derived via `runtime.Caller`, bootstrap hook, challenges — and hand to `challenge.Main`. `--world-home` is core's flag, not the suite's (round-6 C4, superseding round-4 A1's pre-parse): `Main` applies any override before lock derivation, and the engine hands the resolved world to the bootstrap hook, so the override reaches lock, `bin/`, and world exactly once, by construction. The suite parses nothing. `WorldHome` derives from the suite's own source location (`runtime.Caller` — a compile-time path, stable across invocation directories, always valid because the binary is built from the tree it tests), with a flag override for the unusual case.
- **Vocabulary** (earned by repetition in the reference suite, nothing more): the workspace-config author (writes `config.yaml` with the harness-allocated port — the config-fallback bind resolution stays under test, now with a collision-free port), the dead-bind config for recovered-workspace probes, mirror structs (`estateIdentity`, `sliceLabel`, `containerLabel` — decision 7's deliberate duplication), media-tree builders (the nas/usb/usb2/usb3 scaffold), and the job-id capture patterns. **Binding coupling from landed 1a: every mirror field the suite depends on carries `dd:"+required"`.** Core binds mirrors with dd's forgiving default (strict would reject every product field a mirror deliberately omits), so `+required` on the mirror's own fields is the entire drift-detection mechanism — an untagged field degrades `ReadYAML` to silent zero values, which is exactly the lie the census forbids.
- **The go-test face**: `reef/test/gauntlet/gauntlet_test.go` behind `//go:build challenge` — `go test ./...` stays gauntlet-free by mechanism. The invocation is `go test -count=1 -tags challenge ./reef/test/gauntlet`, and `-count=1` is mandatory (round-2 C2): the import seam keeps reef source out of the test binary's cache key, so without it Go's test cache can answer `ok (cached)` for a product it never rebuilt or ran — the silently-passing harness, arriving through the toolchain. That literal is the only supported form anywhere a verdict matters. `gauntlet_test.go` calls the shared bootstrap before constructing the gauntlet (round-3 C2): `-count=1` makes the harness re-run, the bootstrap makes the product rebuild — each closes a staleness door the other cannot. Stage-2 evidence includes the rebuild pin: touch reef source, run the supported go-test literal, verify the binary changed.

## Testing strategy

- **The library proves itself before reef arrives.** The toy-gauntlet matrix in stage 1 is the engine's conscience — resume exactness and checkpoint honesty (byte-compared worlds) are the two that guard the model, not just the code. Quiesce-timeout-as-harness-fault and the three exit tiers pin the error census.
- **The port is the acceptance test.** The parity checklist (port map re-counted at port time) is the definition of "every assertion survives." If any assertion cannot be expressed, the design is wrong, not the assertion — that surfaces as a spec finding, never a silent drop.
- **Cross-surface coherence** rides §18's challenge exactly as the bash has it, now with dd-decoded structured assertions layered over the substring checks.
- **What stays untested**: TTY-pretty rendering (out of scope, decision 8a); the FICLONE fast path on filesystems that lack it (the fallback path is the tested contract; the fast path is exercised wherever the host filesystem supports it); non-linux hosts (linux-first posture — signals and FICLONE; the fallback copy keeps other hosts functional but unproven).

## Risks and watch items

- **The moving reference target.** The recover drills (slice-group-recover stages 4–5) bring parallel recovery workspaces and second/third servers into `exercise.sh`. The model covers the shapes (env-override invocations, multiple supervised processes with distinct binds), but stage 2's effort grows with them; the stage-2 re-census is the control, and the port map table is keyed to sections, not line numbers.
- **Quiesce assumes clean closes.** The server must release its flock and close the WAL on SIGTERM within the bounded wait; a timeout is a harness fault (exit 2), never a finding — a run whose fixture had to be SIGKILLed has an invalid world and says so loudly. If reef's shutdown proves slower than the bound in practice, the bound is a config knob on the process spec, not a softened fault.
- **Snapshot cost is measured, not assumed — and reflink is not expected to be live.** No operating environment here runs btrfs/xfs, so every boundary snapshot is an honest full copy in practice (calibrated with Michael, round-1 walk). Stage 2 records wall-clock and bytes for a full run on the dev filesystem; the seam census's "prohibitive cost" revisit trigger fires on evidence. The per-challenge opt-out exists but ships unused in the reef gauntlet until the measurement argues otherwise.
- **Crash heuristic false positives.** `panic:` / `goroutine ` is the same heuristic the bash uses; reef emits neither in normal output today. A product that legitimately prints "goroutine " would need an escape hatch — deferred until it exists.
- **Resume across binary changes.** `--from` runs today's binary against yesterday's world; label version guards and their kin may legitimately refuse — that is signal, and `--clean` is the reset. Operator knowledge; the transcript makes it visible.
- **136 is today's count.** Parity is asserted against the count at port time. The number in this document is ground truth for its date, not a contract.
- **The register is the product.** The authoring surface (`w.Run` literals, fluent expects) is the spec's design decision; implementation pressure to "simplify" it into option structs or assertion libraries is pressure against the spec. Surface disagreements as findings, not drift.
