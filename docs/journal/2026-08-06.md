- **no PATH fallback for command binaries** — discovered by a test failing for the right reason: `w.Run("reef ...")` on this machine found the *installed* reef. the products these suites guard are usually installed on the machines that test them, so a fallback lets a bootstrap that quietly failed to build be papered over by whatever is on PATH — a green verdict about a build nobody made. resolution: a name with no separator resolves in `bin/` or faults; a path with a separator passes through with an existence check. **a vocabulary that needs a system tool must name its path.**
- readiness is `< 400`, not `< 500`. a 404 on the *declared* readiness path means the server is up but the endpoint the suite expects doesn't exist — treating that as ready pushes the failure into the first real request instead of surfacing it as the break it is. reef's `/api/v1/config` returns 200, so the port is unaffected.
