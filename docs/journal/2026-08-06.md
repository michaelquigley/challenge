- **the unwind mechanism** the WO specifies semantically but never names: a terminal finding (fault/break/crash) panics a private `unwind{class}` sentinel that the engine recovers. challenges are ordinary Go func bodies, so leaving one mid-body is the only way to mean "terminal", and the alternative — returning a zero value and no-oping afterwards — is precisely what the census forbids. `W.record` panics for every class but assertion; `capture()` in helper_test.go is the test-side recovery, and the engine's recover lands in 1c. no product panic can be confused with it: different processes entirely.
- **drift is signal only if the mirror declares what it depends on.** core binds mirrors with dd's *forgiving* default, not `dd.Strict()` — strict rejects input keys the target doesn't declare, and a mirror is deliberately narrower than the state file it reads, so strict would break on every product field the mirror doesn't care about. the mechanism is `dd:"+required"` on the mirror's own fields (note the `+` — dd's tag grammar is `+required`, not `,required`), which makes a rename/removal fail the bind. **coupling for stage 2: the reef vocabulary must tag every mirror field the suite depends on, or ReadYAML degrades to silent zero values.**
